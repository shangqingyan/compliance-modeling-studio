# 诊断与返工手册

本文件是 `model-diagnostics` 的判定基准。脚本输出为初筛信号，最终结论必须结合业务背景和统计常识人工复核。

## 默认阈值

| 信号 | 默认阈值 | 含义 |
| --- | --- | --- |
| test_r2 | `< 0.5` 为 review；`< 0` 为严重 | 模型解释力不足，甚至差于均值模型 |
| normalized_rmse | `> 1.0` 为 review；`> 1.5` 为严重 | RMSE 相对目标标准差过大 |
| mae_ratio | `> 0.8` 为 review | MAE 接近或超过一个目标标准差 |
| shapiro_p | `< 0.05` 为 review；`< 0.01` 且样本量 8 到 5000 为严重 | 残差显著偏离正态 |
| residual_skew | `abs > 1.5` 为 review；`abs > 2.5` 为严重 | 残差分布明显不对称 |
| residual_kurtosis | `abs > 8` 为 review | 残差尾部过重 |
| mean_resid_ratio | `abs > 0.5` | 残差均值相对目标标准差偏移过大，存在系统偏差 |
| heteroscedastic_rho | `abs > 0.3` 且 p < 0.05 | 残差波动随拟合值变化 |
| outlier_ratio | `> 0.05` | 标准化残差超过 3 的比例过高 |
| lag1_autocorr | `abs > 0.7` | 残差序列存在强自相关，需检查时间顺序 |
| residual_slope | `abs > 0.1` | 残差随拟合值仍有线性趋势，模型结构不足 |

这些阈值是启发式，不是法律或统计硬标准。小样本、长尾目标、时间序列等场景应调整并说明。

## 根因定位

### 指标异常：R² 低 / RMSE 高

1. 查看 `data_profile.json` 中 `correlation_with_target`，确认是否有可用特征。
2. 查看模型比较，确认是否尝试了足够的候选模型。
3. 检查目标变换和缩放：右偏目标未做 log1p/Box-Cox 会压低 R²。
4. 检查特征编码：分类变量未编码或错误数值化会丢失信息。
5. 检查数据泄漏：测试集信息泄漏到训练集会虚高，不会虚低；但训练/验证划分错误会导致选型失败。
6. 检查缺失值和离群点：极端值会显著抬高 RMSE。

### 残差非正态

1. 目标本身长尾时，先做目标变换再重看残差。
2. 检查离群点：少量极端样本会同时造成偏度和峰度异常。
3. 若残差右偏且目标为价格、收入、耗时等，优先使用 `log1p` 或稳健回归。
4. 样本量很小（如小于 30）时，Shapiro-Wilk 结果只作参考。

### 残差异方差

1. 做残差绝对值与拟合值的散点图或 Spearman 相关。
2. 对正值目标考虑对数目标变换；对非负目标可换用 Gamma 回归等广义线性模型。
3. 检查是否有分组变量未纳入模型，或某些类别样本方差明显不同。
4. 使用加权回归或稳健标准误，并记录原因。

### 残差自相关

1. 若数据有时间/空间顺序，检查是否遗漏时间变量、滞后项、趋势项或季节性。
2. 不要打乱时间序列后按随机切分训练测试；改用滚动预测或时间序列切分。
3. 重新调用 `$math-modeling` 时明确模型是动态还是静态。

### 分类变量处理修正

- 原始类型为 `object`、`category`、`bool` 或字符串，且 `2 <= unique_count <= 20`：
  - 优先独热编码（`drop='first'`, `handle_unknown='ignore'`）。
  - 若使用 `$tabular-modeling`，把 `--cardinality-threshold` 提高到至少 `max(unique_count)`。
- `unique_count > 20`：
  - 保留频数编码，或使用目标编码/留一编码时必须避免目标泄漏。
- 布尔列：
  - 应作为二分类独热或 0/1 变量，不得与普通字符串混淆。
- 数值型但实际是类别码（如 `education=1..5`）：
  - 先与用户确认，按业务口径改为分类变量再独热编码，或按有序分类处理并说明。

## 返工记录格式

每轮返工必须写入：

```text
轮次: N
原处理方式: ...
新处理方式: ...
原因: ...
效果对比:
  - R2: 旧 -> 新
  - RMSE: 旧 -> 新
  - MAE: 旧 -> 新
  - 残差诊断: 旧 -> 新
是否继续: 是 / 否
```

## 停止条件

- `verdict` 变为 `pass`，且新模型业务可解释。
- 已迭代 3 次仍未改善，或改善小于 1% 且无明确根因。
- 出现禁止项、高风险项，或需要用户授权/额外数据。
